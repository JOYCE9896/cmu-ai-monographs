第八讲：Agent 的监督微调

把录下来的 Agent 运行轨迹变成模型权重：数据怎么选，损失算在哪里，怎样知道训练有效

主讲：Yueqi Song · 2026 年 9 月 17 日
资料来源：课程幻灯片 · 课堂录像

一、从轨迹到权重

1. 一条轨迹长什么样

以 SWE-Gym（Pan 等，2024）为例，一条记录下来的轨迹依次是：系统消息（Harness 的提示词）；用户消息（issue 内容）；助手消息（一段思考加一条 bash 命令）；观测（测试输出）；助手消息（思考加一次文件编辑）；观测（diff）……最后助手提交。Agent 在沙盒里拿到一个 issue 和两个工具（bash 和文件编辑器），产生了思考、命令和命令返回的观测，最后由仓库自己的测试决定这次运行是否成功。

2. 为什么要改权重

第四讲列过更新 Agent 的三个位置。上下文窗口和外部产物（技能、记忆）几秒钟就能更新。改权重的好处是：改一次，之后每次调用都有新行为，提示里不用额外加任何东西。代价是：每改一次都要跑一次训练；你没法打开权重看改了什么；这个改动也没法搬到另一个模型上。

模型从轨迹中学到的东西包括：怎样写出这个 Harness 真能执行的工具调用；对话变长时怎样继续下去，因为它学的轨迹本身就很长；工具结果长什么样，所以它会停下来等结果，而不是自己编一个。但数据里的其他东西也会一起学进去：多余的评论、重复的命令、明明有多种解法却只会一种。

3. SFT 在整个训练流程中的位置

按 token 量看，训练流程是一个不断收窄的过程：预训练约 20 万亿 token（Nemotron 3 Ultra）；中期训练 1.43 万亿（K2 Horizon）；SFT 3320 亿（K2 Horizon）；RL 没有固定语料，靠 rollout 和奖励。越往后，token 越少，每个 token 被筛选得越仔细。

Kimi K3 的流程是：SFT 建立 Agent 的基础能力；RL 在不同推理强度下培养各领域专家；在线策略蒸馏把这些专家合并成一个模型。它的技术报告说，SFT 阶段为后续 RL 建立一个高质量的"冷启动"策略。冷启动指 RL 开始时所用的检查点。在 K3 里，模型在任何 RL 之前，就在 SFT 阶段学会了调用工具和完成长任务。

有人会问：为什么不直接做 RL？DeepSeek-R1-Zero 确实在基础模型上直接做了 RL，完全没有 SFT。但它的下一个模型又把 SFT 加了回来：R1 先用几千条精选样本做 SFT，因为 R1-Zero 的回答会混杂多种语言，很难读懂。

4. SFT 和 RL 的对比

监督微调强化学习
学什么录下来的轨迹，不管是谁生成的自己的 rollout，由奖励打分
信号每个 token 都有目标每条 rollout 一个数字
需要数据和 GPU实时环境、沙盒、可检查的奖励
擅长学工具调用、格式、长任务把模型已经会尝试的能力磨得更好
卡住的情况示范有错、太窄或用完了起点太弱，或奖励无法检查

训练部分一共四讲：本讲 SFT，之后 9 月 22 日、9 月 29 日、10 月 1 日三讲 RL。

二、轨迹怎样变成训练序列

1. 套上聊天模板

把轨迹送进聊天模板，就得到一整串 token。例如一段 Qwen 格式的片段： 

<|im_start|>tool
3 failed, 41 passed
<|im_end|>
<|im_start|>assistant
The test compares floats. Fix it.
<tool_call>
str_replace(...)
</tool_call>
<|im_end|>

<|…|> 这样的标记各是一个特殊 token，其余是 Agent 写的和看到的内容。

2. 损失只算在助手的 token 上

训练时并不是所有 token 都要预测。给每个 token 一个掩码位 $m_t$，只有属于助手输出的 token 为 1，其余为 0。损失是：

$$\mathcal{L}(\theta) = -\sum_{t:\, m_t = 1} \log p_\theta(x_t \mid x_{<t})$$

最小化它，就是在给定前面所有内容的条件下，提高每个录下来的动作的概率。系统提示、用户消息和观测只作为条件上下文，不作为预测目标。道理很简单：工具的输出是环境给的，模型不应该学着自己生成它。

3. 掩码怎样构建

分三步：模板把对话渲染成一个字符串，同时记下每段助手内容从第几个字符开始、到第几个字符结束；分词时把字符位置转换成 token 位置；助手范围内的 token 标 1，其余标 0。训练开始时，角色信息已经没有了，训练器只看到字符串和这些掩码位。

框架设置项掩码怎样产生
TRLassistant_only_loss=True模板渲染时标出助手范围（需要模板里有 {% generation %} 标记）
Axolotlroles_to_train、train_on_eos在渲染后的字符串里找每一轮的角色头
LLaMA-Factorytrain_on_prompt、mask_history编码时把整轮标记为训练或忽略

三个框架做的是同一个决定，只有 TRL 把它放在模板里。

4. 轮次结束 token 必须算进损失

看这一段：<|im_start|>assistant 换行，"I'll run the failing test."，工具调用 bash(cmd="pytest -q")，<|im_end|>。开头的角色头 <|im_start|>assistant 在推理时由 Harness 提供，永远不是预测目标。但结尾的 <|im_end|> 是模型自己要生成的停止信号，必须在掩码内，否则 TRL 的文档说"模型可能学不会停下来"。

而且"轮次结束"其实是三种不同的事：结束这条消息、交给工具执行、完成整个任务。Kimi K3 的模板用不同的 token 把它们区分开，比如 [end_of_msg]。

5. 推理内容要不要训练

对 <think>…</think> 这样的推理块，有两个开关要分别决定：它是否留在上下文里，以及它是否参与训练。留在上下文里，它能解释后面的动作；参与训练，它就变成模型自己写推理的风格。Nemotron 的做法是：因推理预算被截断的推理内容保留在上下文里，但人为截断的那个位置不算损失。

6. 助手轮次内部的加权

BalanceSFT（Hao 等，2025）指出一个问题：推理文字很长，在损失里占了大头，而真正需要做对的是短短的工具调用。它提出两个组件：SSB 学一个权重，在损失里平衡推理 token 和工具调用 token；HDR 对困难样本重新采样。多轮任务上的提升比单轮更大，两个基础模型上都是如此。

7. 按样本数配比和按 token 数配比不一样

MAI-Thinking-1（微软 AI，2026）按样本数平衡了数据配比，但损失是按 token 算的。STEM 和编程的轨迹长得多，最后几乎占了全部 token。所以按轨迹条数平衡配比之后，一定要检查换算成 token 是什么比例。

8. 一个没人做过的实验

主讲人说，他们找不到任何已发表的实验，专门改变 Agent SFT 的掩码并测量影响。仔细做过掩码实验的都是单轮指令微调，不是 Agent。唯一一个"不掩码提示反而有帮助"的案例（Instruction Modelling，Shi 等，2024；另见 WIT，Chatterjee 等，2025），条件是提示长、回答短、数据少，而 Agent 轨迹在这三点上正好相反。这个实验在 8B 规模上很便宜，但还没有人做。

三、选择哪些轨迹

1. 轨迹从哪里来

谁跑的任务全部保留只保留通过的
更强的模型普通蒸馏SWE-Gym、Nemotron、OpenThoughts-Agent
模型自己MAI（在自己的推理运行上）专家迭代（下一讲）

大多数 Agent SFT 数据在右上格：更强的模型能写出比学生更好的轨迹，任务自带的测试让筛选好轨迹变得便宜。下面一行是模型自己生成训练数据，反复循环就是专家迭代，下一讲会讲。

2. 从更强的模型蒸馏

SWE-Gym 让 GPT-4o 和 Claude 跑任务，得到 491 条通过仓库测试的轨迹。只用这 491 条微调一个 32B 的 Qwen 模型，它在两个 SWE-Bench 子集上的分数都提高了 10 分以上。在任务集不变、只增加采样轨迹数量的实验里，准确率到采样预算用完时仍在上升。他们不缺任务，缺的是采样更多轨迹的算力。

3. 成功的轨迹里也有坏习惯

Nemotron 3 Ultra 的报告举了几个例子，这些运行都通过了测试：有的只读文件从不修改；有的大部分轮次都在"改一下、跑一下测试"地循环；有的在最终补丁里留下了 print( 调试语句。报告的原话是，这些"如果直接用作 SFT 数据，会教给模型不好的行为"。因为损失会复制每一个动作，不管好坏，模型会把乱七八糟的过程和修复一起学进去。

4. 按形状过滤

OpenThoughts-Agent（Raoof 等，2026）发现，效果最好的过滤方法只是数轮次，丢掉少于 5 轮的运行。轮次只说明一次运行做了多少工作，不说明做得好不好：一个 4 轮的干净修复会被丢掉，一个 40 轮的混乱运行会被保留。但平均来看，它仍然有帮助。

5. 选择教师模型

同一篇论文比较了 5 个教师模型。GPT-5.3-Codex 在基准上本身是最强的，但用它的轨迹训练出来的学生最弱。排行榜名次在这里给出了错误的信号。相比之下，试两个教师、保留更好的学生，成本很低。

6. 任务来源最重要

在所有因素里，任务来源对结果的影响最大。不同来源帮助不同的基准，所以在调其他参数之前，先把精力花在这里。混合最好的 4 到 8 个来源；再多也没有帮助。

数据扩展的实验：两条曲线都从同一个 1 万条的数据集出发，只是额外数据的来源不同。在同样的任务上增加更多运行，曲线会变平；增加新任务，曲线持续上升。

7. 课堂讨论

同一个任务跑回来三条轨迹：A 是 4 轮就解决的短运行；B 是一条长运行，做错了一次编辑，看到测试失败后恢复过来；C 在 11 次什么都没改变的尝试之后才解决。你要保留哪些？保留的那些，哪些动作算损失？"最少轮次"过滤器会在哪些答案上判断错？

四、多个数据集统一格式

每个 Agent 数据集都由不同团队用自己的格式构建。比如同样是网页，有的保存 HTML，有的保存可访问性树。要把两个数据集放在一起训练，就得先写两个定制的转换器。

Agent Data Protocol（ADP，Song 等，ICLR 2026 口头报告，主讲人是第一作者）提出一种统一表示：把每个数据集读一遍，改写成有类型的动作和观测。对于网页，HTML 和可访问性树都保留，不必二选一。这样每个数据集只转换一次，每个 Harness 也只适配一次，而不是每一对组合都写一个转换器。

数据统一之后，还要针对要训练的 Harness 渲染出来。OpenHands、SWE-Agent 和 AgentLab 的动作不同，同一条轨迹在各自那里看起来不一样。系统提示和上下文变长时的处理方式也在这一步设定。渲染完要检查：工具调用能否被解析，每个调用是否都带有思考，对话是否以正确的方式结束。

多样性和专用数据的对比：在同样的 Harness、同样的模型、同样的评估下，只改变训练数据配比。用混合数据训练，比用对应领域的单一数据训练效果更好，即使是在那个领域自己的基准上。

2. 混合专家模型的路由

前沿模型大多是混合专家模型（MoE）：模型里有很多"专家"子网络，每个 token 只被路由到其中几个。而公开论文里微调的模型大多是稠密模型。用窄的 Agent 数据微调 MoE 时，少数几个专家会接收大部分 token，其他专家几乎不被训练。MAI 的做法是：在 SFT 阶段把路由的负载均衡约束加得非常强，比 RL 阶段强一千倍，并把 dropout 提高到 0.15。

3. 拼接完整对话

训练用固定长度的序列。拼接（packing）是把几条对话装进一个序列，而不是用大量填充符补齐。Nemotron 3 Ultra 的做法：每条对话放进剩余空间最贴合的那个序列；任何对话都不切分、不截断，这是为了避免幻觉而有意做的选择；相同的提示不放进同一个序列；拼好后再打乱顺序。

4. 模板漂移

Transformers 文档写道："聊天模板应该始终和模型训练时的格式一致。"训练用的模板和部署用的模板必须一模一样，连空白字符都要一致。有一个隐蔽的问题：同一条轨迹渲染两次，一次后面接了一条工具消息，一次没有，可能得到两个不同的字符串。原因是模板里有条件判断的思考块，追加工具消息后，前面助手轮次的渲染方式变了，前缀就对不上了。

5. 已公开的训练材料

K2 Horizon 的模型卡有一张逐阶段的训练表，包括步数、token 数、序列长度和每个阶段的目的，上面的配置数字就来自这里。它还链接了 Weights & Biases 上的训练记录，可以看真实的损失曲线，并提供每个阶段的中间检查点。Nemotron 把后训练的检查点、训练数据和配方一起公开了。读一读这些材料能学到很多。

六、怎样知道训练有效

1. 训练和实际运行的错位

训练时每次只评判一个动作，而且总是接着录下来的轨迹往下走。部署时没有录像，模型的每一个动作都会改变它接下来看到的内容。假设同一个前缀（issue 加第一次编辑）之后，录下来的是编辑 A，测试通过，提交。如果模型做了一个看起来合理、但不同的编辑 B，测试失败，它就进入了训练中从未出现过的状态。损失低并不能保证它在那里会怎样。这个问题和 DAgger（Ross 等，2011）研究的模仿学习问题相同。

2. 在目标 Harness 中评估

在相信任何数字之前，先检查能否把 20 个样本训练到过拟合。如果损失降不下来，问题出在上游。然后在 Harness 里运行模型，在结果可以检查的任务上评估。读别人公布的数字要小心，有时它们是几个 Harness 里最好的那个。数据划分要和想说明的结论匹配：同一个任务的所有运行放在同一边；如果要说明模型能泛化到新仓库，就按仓库划分。

3. 跨 Harness 的稳健性和其他能力的退化

在一个系统里收集的轨迹，除了任务本身，还会教给模型这个系统的惯例。在多个 Harness 里收集数据，是各家实验室避免训练出"只能在一个系统里用"的模型的办法。

训练一种能力，其他能力也会跟着变，不管你有没有测量。数据配比是控制手段，而按样本数平衡不等于按 token 数平衡。所以那些你没打算提升的能力也要评估。

七、交给 RL

OpenThoughts-Agent 的实验显示：完全不做 SFT 直接做 RL，基础模型几乎没有变化；只做 SFT，离 SFT 加 RL 能达到的水平差得很远。最好的配方是从一个"有意没有训练到自身最佳分数"的检查点开始 RL。论文的原话是："当 SFT 模型的选择考虑到了 RL 时，RL 带来的提升最大。"

八、小结

Agent 的 SFT 把轨迹套上聊天模板变成一串 token，只在助手生成的 token（包括轮次结束 token）上算损失。数据选择比训练参数更重要：任务来源影响最大，新任务比同一任务的更多轨迹更有用，教师模型要实际试，成功的轨迹里也可能有坏习惯。多个数据集可以通过统一格式合并，再针对目标 Harness 渲染。训练时要注意 MoE 路由、拼接和模板一致性。评估要在目标 Harness 中跑真实任务，并检查其他能力是否退化。SFT 最终是为 RL 准备一个好的起点。
